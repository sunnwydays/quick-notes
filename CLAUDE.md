# Working on Quick Notes

See README.md for how the app works and how it deploys (every push to `main` goes live).

## Commits

- One commit per feature or fix. When one request covers several changes, split them into separate commits, even if they touch the same files.
- Commit small, simple changes (copy tweaks, styling, a contained feature that doesn't need checking on a phone) as soon as they're done, without waiting to be asked.
- Wait before committing anything that needs testing on a device first (touch gestures, keyboard behaviour, sync, data migrations), or anything risky. Say what to test instead.
- Commit, but don't push unless asked: pushing deploys to production.
